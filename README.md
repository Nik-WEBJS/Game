# Business Tycoon Wiki (Short Guide)

Игровой симулятор роста digital-продукта: продукт, фичи, производство, инфраструктура, поддержка, конкуренты и кампания.

## Быстрый старт проекта

```bash
npm install
npm run dev
```

Открой `http://localhost:3000`.

## Ключевая логика денег (важно)

Если у тебя только `1 developer`, почти всегда будет убыток. Это ожидаемое поведение текущей модели.

Почему:
- выручка сильно зависит от `audience`;
- `audience` растет в основном через `marketing`;
- продукт сначала проходит `prototype -> beta -> release`;
- пока нет рабочей воронки, расходы (зарплаты/инфраструктура) уже списываются.

Правило долга:
- баланс может уходить в минус, и траты в этот момент разрешены;
- поражение по банкротству наступает только при `money <= -$500,000`.

## Краткий гайд: как выйти в плюс

1. Стартовая команда: минимум `developer + marketing` (опционально `manager`).
2. Первые недели: доведи продукт до `release`, не раздувай штат раньше времени.
3. Производство: держи очередь ресурсов (`code/design/ops/support`), иначе фичи и апгрейды встанут.
4. Первый путь фич: `core_account -> growth_analytics -> mon_subscription`.
5. Инфраструктура: при росте `server load` заранее апгрейдь хостинг.
6. Support: следи за backlog, он бьет по `satisfaction/churn` и тормозит рост.
7. M&A-lite: в mid-game ускоряйся через `buy_user_base` / `brand_boost` при финансовой подушке.

## Антипаттерны (ведут к проигрышу)

- играть с одним сотрудником весь ранний этап;
- нанимать много людей до появления стабильной продуктовой воронки;
- игнорировать маркетинг;
- игнорировать `server load` и `support queue`;
- пытаться качать все фичи одновременно без производственных ресурсов;
- жить в глубоком минусе слишком долго и упираться в порог `-500k`.
